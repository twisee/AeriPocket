# AeriPocket · 个人记账软件

此目录是 ControlECO 的直接定制分支，未采用旧版个人 App 的数据库、流水页面或通知采集引擎。

- 上游：https://github.com/ArrogHie/ControlECO
- 基线提交：bd3152363c499bc6cb7453d73d2d146ccf78a0be（上游版本 1.0.6）
- 代码许可：沿用仓库 LICENSE 中的 GPL-3.0，保留原项目说明与贡献者信息。
- 当前正式版本：1.0.1；包名 com.twisee.wallet.eco。
- 1.0.1 修复补充信息输入后返回金额编辑，增加跟随主题色的四则计算键盘，详见 [更新说明](docs/releases/1.0.1.md)。
- 旧版个人 App com.twisee.wallet 与原版 ECO 均可并存。旧账本不会自动迁移；请在新版重新导入导出的账单。

## 复用与修改边界

沿用原项目的 Room 账本、账户、流水筛选/搜索/多选、导入界面、CSV/XLSX 读取、通知采集、商户规则、独立记账和编辑页、统计页与设置。

定制部分：

1. 爱丽丝首页独立展示层与角色素材包。实际预算决定姿势；进度动画不参与姿势选择。加载完成前不显示错误的 0% 人物；人物淡入；点击使用原始双帧眨眼、整个人物按压回弹和装饰性“+1￥”，不写入账本。小型毛玻璃入口可点击/上滑进入概览。
2. 首页无日历、无记账按钮；底部首页/流水/概览/个人。仅流水右下角有记一笔，打开上游独立页面。
3. 默认黑白灰主题，保留彩色人物，增加暖黄色可选主题；新花朵/账本导航图标与爱丽丝拿账本头像图标。
4. 默认支出四类：餐饮、购物、娱乐、日常。预算沿用上游固定月预算/分类预算，按月持续生效，无须每月重填。
5. 退款事件留在数据库作去重、账户对账依据，流水不另列为正收入。精确关联原支出后，原金额划线并显示实付。部分退款按净额统计，跨月退款调整原消费月份；无法精确匹配的事件进入待确认页。不得以同额、相近时间自动猜配。
6. Room 14→15 增加 refundedCents/refundExpenseId；撤销只影响精确关联的退款，避免误删同额的其他退款。
7. 支付宝已关闭的原单，仅存在成功退款原交易号证据时导入。收益发放（含短横线、日期）、明确转账收款按收入识别；充值/提现/理财本金仍跳过。
8. 导入应用已有商户分类规则；例如将学校食堂商户编辑为餐饮后，后续导入同商户优先餐饮。保留原项目的商户规则管理页。
9. 禁用上游 APK 自动更新，避免定制版被错误引导安装原版。通知采集沿用 ECO，无障碍页面采集默认关闭；权限仍需用户在系统设置主动开启。
10. 流水与概览默认结余卡、个人页预算卡使用确认的爱丽丝抱杯花卉图；无底部整条遮罩。原有自定义图片优先，仍可从流水更换封面。

角色包当前位于 app/src/main/assets/characters/aerith，包含 pack.json 与五套双帧素材。架构预留换角色空间，尚未提供用户导入角色包的设置界面。人物为用户指定的《最终幻想》角色衍生素材，不代表拥有原角色 IP。

## 构建和验证

JDK 17、Android SDK 35、Build Tools 35.0.0。配置 ANDROID_HOME 或本机 local.properties，然后在 Windows PowerShell 执行：

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleRelease
```

本次环境使用已有 Gradle 8.9 运行同一项目；仓库原版 wrapper 仍为 Gradle 8.10.2。

可选本地私有账单回归，文件必须位于仓库外；缺少参数时该测试跳过：

```powershell
.\gradlew.bat :app:testDebugUnitTest '-PlocalBill=你的本机账单路径.csv'
```

测试只输出条数与关联结果，不输出用户姓名、单号、商户明细、金额或原文件内容。发布目录与源码压缩包不包含真实账单、测试数据库、local.properties、密钥或构建缓存。

PersonalVisualTest 使用 Android 35 / Robolectric 原生图形渲染实际 Compose 页面，截图仅含合成演示记录。它验证页面结构与操作入口，不能代替小米 13 的真实启动、权限、通知兼容性及耗电测试。

## 0.3.7 原版眨眼与点击回应

- 按确认预览保留原始睁眼、闭眼两张完整人物图，每一时刻只绘制一帧；撤掉局部眼部叠加和混合，不生成新眼睛、不放大脸部。这次没有新增中间帧。
- 点击后约65ms闭眼，保持约455ms，再恢复原图；一次回应约650ms。连点不打断或延长当前眨眼，每次点击独立飘出“+1￥”，约1.05秒消失，只作视觉反馈，不增加收入或影响预算。
- 按住时整个人物缩至96.5%，松开约220ms恢复，回弹不超过原尺寸；快速轻点也保留短暂按压反馈。上滑进入概览仍可操作。
- 五档人物共用此逻辑。原PNG素材、20%分档、真实账本与筛选删除逻辑保持原样。关闭界面动画时不播放点击特效；离开前台停止并清理点击回应。

## 0.3.4 筛选批删修复与紧凑月格

- 修复“收入/分类筛选 → 批量管理 → 全选”错误选中未筛选流水的问题。全选仅作用于当前已加载范围内符合筛选条件的记录，不受列表首屏分页限制。
- 切换收支或分类筛选时清空旧勾选；后台数据更新时剔除已离开筛选范围的选择。删除时再次取当前筛选范围内的已选编号，并在确认期间固定编号快照；新到的流水不加入这次删除。
- 确认框明确显示删除条数和收支/分类范围。零选择时删除按钮禁用。按周期/年删除仍是独立的“全部”操作，额外标明不受筛选影响。
- 月份方格按用户确认的预览改为每行 6 格、共 2 行，高度 48dp；选中后点上方“查看…月流水”才跳转。每日格子保持原尺寸。
- 此修复不会自动恢复之前已经误删的记录。未访问或修改用户手机数据库；本地验证只使用合成数据。

## 0.3.1 基础流程修正

- 恢复“个人”导航，设置作为个人页的二级入口；旧测试版升级时一次性切换为黑白灰，之后保留用户自行选择的主题。
- 导出原单已经带有退款累计金额时，手动关联同一退款事件不会再次扣减；支持从待确认页关联原单已全额退款的导入记录。
- 按月/年删除仅处理界面可见的流水及其关联退款，不会因本月包含退款到账事件而删坏别的月份原单。
- 导入预览不再把退款计入收入计数，说明与最终账本行为一致。
- 修正冷启动开屏结束后进度条不重播的问题，人物姿势始终按真实预算选取。
- 首次启动的默认分类/账户在一个事务内初始化，避免启动并发造成缺项或重复。
- 权限就绪只检查已启用通道的必要权限，不再要求无障碍、短信、悬浮窗全部开启。
- 消费日历与其他新工具延后，本版不添加。
